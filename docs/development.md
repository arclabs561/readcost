# Development

```sh
uv sync && uv run pytest                       # or: pip install -e '.[test]' && python3 -m pytest
uv run pytest -n auto                          # the same tests on every core, as CI runs them
uv run readcost check . --fail-on block        # CI runs readcost on its own repo
uv run readcost check README.md docs --fail-on advise   # after changing documentation
uv run --group eval scripts/eval_simplifications.py REF   # scripts without inline metadata
uv run scripts/fetch_eval_corpus.py ref/eval   # scripts with inline metadata bring their own
uv run --group eval scripts/build_lexicon.py   # also needs nltk's WordNet data
uv run scripts/build_default_profile.py ref/eval   # after fetch_eval_corpus.py
```

Scripts with inline metadata that import readcost install this checkout, not
the release on PyPI.

## Tests

Most command-line tests call `readcost.cli.main` inside the test process and
share one loaded spaCy model (`tests/cliproc.py`, `tests/conftest.py`); a few
start a real `python -m readcost`. `READCOST_TEST_SUBPROCESS=1 uv run pytest`
starts a real process for every one of them, which takes about five times as
long. `tests/conftest.py` also clears the git identity, the user's git config
and the `READCOST_*` and `GITHUB_*` variables, so a test gives the same
result in any shell. CI installs with `uv sync --locked`, so change
`uv.lock` (`uv lock`) in the same commit as a dependency in `pyproject.toml`.

Some tests check documentation against what readcost prints:

- the README's example blocks (`tests/test_diagnostics.py`);
- the README's terminal image (`tests/test_terminal_svg.py`); rerun
  `scripts/terminal_svg.py` when the output changes;
- the rule names in the README's "What it flags" table (`tests/test_lsp.py`);
- the examples in [rules](rules.md#examples) (`tests/test_detectors_batch.py`);
- the `readcost compare` output in [reading time](reading-time.md)
  (`tests/test_compare.py`).

`scripts/readme_gallery.py` regenerates the real output in
[rules](rules.md#real-output).

## Prose check on pull requests

On every pull request, `scripts/ci_prose.py` also checks the title, the
description and each commit message (`--format commit`). A commit message
that reaches "block" fails the check. Findings in the title and description
are only warnings, since many findings are wrong. The check also fails on AI
attribution in commits, in the description or in added lines:

- session links;
- co-author trailers;
- "generated by" or "generated with" lines;
- an Anthropic no-reply author.

Run it locally with `python scripts/ci_prose.py --base main`.
